Supabase 開源 PostgreSQL 雲端後端

透過自然語言指揮全球最強大的開源 BaaS (Backend-as-a-Service) 平台 Supabase。Antigravity AI Agent 能直接設計完整的 PostgreSQL 關聯資料表與外鍵、編寫高強度的 Row Level Security (RLS) 安全策略、自動導出前端 TypeScript 型別、並部署邊緣運算 Edge Functions。

1. 功能概述與生態定位

相較於 Firebase 的 NoSQL 文檔模型，Supabase 堅持採用世界級的關聯式資料庫 PostgreSQL。Antigravity 的 Supabase 擴充套件讓全端工程師在幾秒鐘內建立正規化的資料庫結構並完成全套安全防護：

原生 PostgreSQL 資料庫

完整支援外鍵關聯 (Foreign Keys)、CHECK 約束、PostGIS 地理資訊、pgvector 向量檢索與 EXPLAIN 慢查詢優化。

Row Level Security (RLS)

資料庫級的精細權限控制，客戶端前端可直接調用 SDK 查詢，由資料庫核心確保用戶只能讀寫屬於自己的資料列。

TypeScript 型別自動生成

自動從線上 Schema 即時抽取並生成 `database.types.ts`，讓前端 React/Vue 享受編譯期的 100% 型別安全防護。

2. 這個功能能做什麼？

Migration 結構遷移腳本自動生成

用自然語言描述業務需求，AI 自動為您產出具備 Transaction 交易保護的 SQL Migration 檔案（包含 CREATE TABLE, ALTER TABLE 與 INDEX 建立）。

RLS 安全策略智慧審計與自動修復

自動掃描未開啟 Row Level Security 的高危險資料表，生成精準的 `CREATE POLICY` 語法（例如限定 `auth.uid() == user_id` 或基於 RBAC 角色的存取判定）。

Deno Edge Functions 邊緣運算快速交付

在幾秒鐘內為專案搭建並部署基於 Deno 的伺服器端無狀態微服務，處理 Stripe Webhook 驗證、敏感金鑰調用與批次郵件寄送。

Storage 私有檔案儲存與簽署 URL 管理

建立私有 (Private) 儲存桶，設定嚴格的 Storage RLS 規則，並自動生成具備有效期限的 Signed URLs 供受授權用戶下載機密檔案。

3. 核心工具架構與 MCP API

MCP 工具名稱 核心參數 回傳型態 功能說明與最佳實務
supabase_sql_query query Query Results 執行原生 SQL DDL/DML 語法，支援 Migration 腳本執行與 EXPLAIN 分析
supabase_get_schema schema: 'public' Schema Tree 讀取資料表結構、欄位型態、主外鍵關係、預設值與索引定義
supabase_generate_types schema TypeScript Defs 自動生成對齊 live 資料庫的 TypeScript 介面定義檔案
supabase_manage_rls table_name, action Policy Object 開啟或審查特定資料表的 Row Level Security 狀態與目前生效的 Policies
supabase_deploy_edge_function function_name, files Deploy Result 一鍵將本機 Deno TypeScript 程式碼發布至 Supabase 全球邊緣伺服器

範例 01 全端工程師：多租戶 (Multi-tenant) PostgreSQL 資料庫綱要與外鍵設計

情境描述： 打造全新 B2B SaaS 平台，需設計隔離的 Organizations、Users、Projects 三層資料表結構，並自動配置級聯刪除 (ON DELETE CASCADE) 與時間戳記。 

請使用 `supabase` 外掛為我設計並執行資料庫 Migration：
1. 設計一個支援多租戶架構的資料表體系：
   - 資料表 1：`organizations` (id UUID PK default gen_random_uuid(), name text, slug text UNIQUE, created_at timestamptz default now())
   - 資料表 2：`org_members` (org_id references organizations on delete cascade, user_id references auth.users on delete cascade, role text default 'member', PRIMARY KEY (org_id, user_id))
   - 資料表 3：`projects` (id UUID PK, org_id references organizations, title text, status text default 'active', created_at timestamptz)
2. 為 `projects.org_id` 建立 B-Tree 索引以加速跨租戶過濾。
3. 產生完整的 SQL 腳本並呼叫 `supabase_sql_query` 在資料庫中直接套用。
4. 驗證資料表建立成功並回報外鍵拓撲關係。
預期執行成果：

AI 自動生成語法嚴謹的 PostgreSQL DDL 並安全執行，外鍵約束與索引配置一應俱全。

範例 02 DBA / 資安工程師：Row Level Security (RLS) 策略嚴格審計與資料越權防護

情境描述： 前端使用者可直接透過 Supabase JS Client 查詢資料，必須確保用戶絕對無法讀取或修改不屬於自己機構的專案與帳務紀錄。 

請對我的 Supabase 資料庫進行全面的 RLS 安全審計：
1. 查詢 public schema 下所有資料表，找出尚未開啟 RLS (`rowsecurity = false`) 的高危險名單。
2. 針對 `projects` 資料表強制啟用 RLS：`ALTER TABLE projects ENABLE ROW LEVEL SECURITY;`
3. 撰寫細緻的 CRUD 安全政策 (Policies)：
   - SELECT Policy：僅允許該專案所屬組織的成員讀取 (`EXISTS (SELECT 1 FROM org_members WHERE org_members.org_id = projects.org_id AND org_members.user_id = auth.uid())`)。
   - INSERT Policy：僅允許具有 `admin` 或 `owner` 角色的組織成員新增。
   - UPDATE Policy：限定專案建立者或組織管理員方可修改。
4. 執行安全驗證測試，確認匿名訪客 (anon key) 查詢直接被資料庫阻擋回傳空集合。
預期執行成果：

AI 生成強健的 RLS 政策並套用，徹底消除水準越權 (BOLA) 安全隱患。

5. Supabase 四大核心架構守則

守則一：所有 Public 表格預設開啟 RLS

只要資料表暴露在 `public` schema 下，必須執行 `ENABLE ROW LEVEL SECURITY`。未定義 Policy 的表格會被預設拒絕所有存取，保障資料庫安全無虞。

守則二：區分 Anon Key 與 Service Role Key

前端瀏覽器或 App 中只能暴露帶有 RLS 保護的 `anon` 公鑰；繞過 RLS 的 `service_role` 萬能私鑰只能存放在伺服器環境或 Edge Functions 中。

守則三：外鍵欄位必建索引 (Foreign Key Indexes)

PostgreSQL 不會自動為外鍵建立索引。所有帶有 `REFERENCES` 的關聯欄位（如 `user_id`, `org_id`），務必主動建立 B-Tree 索引，以防止跨表 JOIN 導致全表掃描。

守則四：以 Migration 追蹤資料庫異動

嚴禁直接在線上 Dashboard 手動點擊修改欄位型態。所有結構異動必須保存為包含時間戳的 SQL Migration 檔案並納入 Git 版本庫管理。

7. 常見問題與除錯指南 (FAQ)

Q1: 為什麼前端能成功連線，但 SELECT 查詢出來都是空的陣列 []？

這是因為該資料表開啟了 RLS，但您尚未建立任何允許 SELECT 的 Policy。請調用 `supabase_manage_rls` 建立對應的讀取策略，或者在除錯時暫時確認 policy 條件是否誤判。

Q2: Supabase 與 Firebase 在選擇上有何關鍵差異？

核心差別在於「資料結構」。Firebase 是 NoSQL 文檔庫，適合簡單階層與高併發寫入；Supabase 是完整 PostgreSQL 關聯資料庫，具備強大 JOIN 關聯、複雜聚合查詢、外鍵完整性與豐富開源生態。

Q3: 如何在本機無網路環境下進行開發？

安裝 Supabase CLI 並執行 `supabase start`，即可在本地 Docker 啟動包含 Postgres, Auth, Inbucket 郵件模擬器與 Studio 網頁介面的完整獨立環境。
