Google Cloud & Gemini Developer

透過自然語言指揮 Google Cloud Platform (GCP) 全套雲端資源與 Gemini 前端多模態模型。從百萬 Token 影像/音訊深度理解、Cloud Run 無伺服器容器自動部署，到 BigQuery PB 級數據庫查詢與 FinOps 成本審計，Antigravity 將雲端架構師與 AI 開發者的工作流濃縮為毫秒級的自動化對話。

1. 功能概述與生態架構

在現代雲端原生與生成式 AI 開發中，開發者常需在 GCP Console、gcloud CLI、BigQuery Studio 和 Gemini API Documentation 間頻繁切換。Antigravity 的 Google Cloud 系列外掛將這三層雲端能力徹底整合為一：

Gemini API Suite

整合 Gemini 2.0 Flash / 1.5 Pro 原生多模態 API、長達 2,000,000 tokens 上下文分析、結構化 JSON Schema 輸出與 Function Calling 規格生成。

Cloud Developer CLI

驅動 gcloud 核心功能：Cloud Run 服務部署、Cloud Functions 事件觸發、IAM 最小權限審計與即時日誌流追蹤。

BigQuery Data Agent Kit

支援 Dry-Run 預估掃描位元組數、PB 級巨量資料 SQL 自動優化、分區 (Partitioning) 與叢集 (Clustering) 健檢及自動報表管線建置。

2. 這個功能能做什麼？

無伺服器微服務快速交付 (Cloud Run)

只需一句指令，Antigravity 可為後端程式碼產生最佳實務 Dockerfile、設定 Cloud SQL Auth Proxy 連線、掛載 Secret Manager 機密環境變數，並一鍵編譯部署至 Cloud Run 支援自動水平擴展。

BigQuery SQL 自動優化與防暴衝審計

內建安全查詢機制，在執行任何 SQL 前必定執行 dry-run 估算查詢資料量，主動阻擋全表掃描（Full Table Scan），並自動改寫為分區日期過濾語法，省下昂貴查詢帳單。

Gemini 2.0 百萬多模態上下文分析

直接將本機 1 小時教學錄音檔、高解析度產品設計影片或上百頁技術規格 PDF 送交 Gemini 1.5 Pro / 2.0 Flash 進行毫秒級幀定位、逐字稿交叉比對與多模態問答提取。

IAM 權限最小化與資安自動健檢

掃描 GCP 專案中所有的 Service Account 角色配置，自動偵測過度授權的 roles/editor 或 roles/owner，生成最小權限自訂角色 (Custom Role) 定義。

情境描述： 需在 Node.js/Python 前端微服務中整合 Gemini 2.0 Flash，將使用者上傳的發票相片直接解析為符合嚴格 TypeScript 介面的 JSON 格式，並拒絕任何非規格文字回覆。

1. 傳入我當前專案資料夾下的發票測試照片 `tests/fixtures/receipt_tw_01.jpg`。
2. 要求模型嚴格以 JSON Schema 格式輸出，不得含有任何 Markdown 標記或額外問候語。
3. JSON Schema 結構要求如下：
   - `invoice_number`: string (格式如 AB-12345678)

5. 完成後將輸出結果存入 `outputs/parsed_receipt.json`，並為我生成一段可直接運行的 Python 驗證測試腳本。
預期執行成果：

Antigravity 調用 gemini_generate_content 配置 response_mime_type="application/json"，解析發票圖片並精確寫入 JSON 檔案，附帶 100% 欄位吻合的單元測試腳本。

5. FinOps 成本控制與資安四大防線

防線一：BigQuery 查詢強制 Dry-Run

Antigravity 內建安全審查機制，在未提供分區條件或未估算位元組數前，絕不盲目執行 TB 級查詢。強烈建議在 BigQuery 中設定「Per-Query Bytes Billed Limit」專案層級上限。

防線二：機密資訊一律外置於 Secret Manager

禁止在任何 Prompt、環境變數或程式碼中硬編碼 GCP 服務帳戶私鑰或資料庫密碼。應一律透過 GCP Secret Manager 掛載，並由 IAM 授予特定 Cloud Run 服務唯讀權限。

防線三：Gemini API Token 預先計數 (Count Tokens)

在上傳大量長影音或高解析度圖片至 Gemini API 前，先調用 gemini_count_tokens 工具評估總消耗量，防止意外突破 Tier 速率限制 (RPM/TPM)。

防線四：拒絕全域 Owner/Editor 原始角色

生產環境之 CI/CD 部署流水線或背景服務應嚴格依據最小權限原則 (Principle of Least Privilege)，使用自訂角色 (Custom Roles) 或精細的官方 Job Runner 預定義角色。

6. 安裝與認證設定 (ADC 授權)

Google Cloud 系列擴充功能支援 Google 官方標準的應用程式預設憑證 (Application Default Credentials, ADC)，無需手動管理任何高風險的 JSON 憑證私鑰檔。

1 安裝外掛套件

在 Antigravity 對話框中輸入安裝指令或點選擴充套件市場：

/plugin install antigravity-plugins-official/plugin/gemini-api
/plugin install google-cloud-developer
/plugin install data-agent-kit-plugin
2 本機 gcloud CLI 登入與 ADC 授權綁定

在終端機中執行標準登入流程，完成瀏覽器 OAuth 驗證授權：

# 登入 gcloud CLI
gcloud auth login

# 生成應用程式預設憑證 (ADC)，供 Antigravity 及 SDK 自動存取
gcloud auth application-default login

# 設定預設專案與區域
gcloud config set project [YOUR_GCP_PROJECT_ID]
gcloud config set compute/region asia-east1
3 設定 Gemini API 金鑰（如需獨立調用 API）

在環境變數或 Antigravity 設定檔中提供 Gemini API Key：

# Linux / macOS
export GEMINI_API_KEY="AIzaSy..."

# Windows PowerShell
$env:GEMINI_API_KEY="AIzaSy..."

7. 常見問題與除錯指南 (FAQ)

Q1: 執行 gcloud 指令或 BigQuery 時出現「Re-authentication required」或憑證過期？

這是因為 Google Cloud 的 OAuth Session 具有生命週期限制。請在終端機中重新執行 gcloud auth application-default login，完成瀏覽器驗證後，Antigravity 便會自動取得新權杖並恢復正常運作。

Q2: Gemini API 呼叫時遇到 429 Resource Exhausted (配額不足) 該如何處理？

429 通常代表達到了每分鐘請求數 (RPM) 或每分鐘 Token 數 (TPM) 的上限。免費方案 (Free Tier) 限額較嚴格；若用於生產或頻繁開發，建議前往 Google AI Studio 或 GCP Console 綁定帳單帳戶升級為 Pay-as-you-go 方案，並在 Antigravity 中選用輕量且高吞吐的 gemini-2.0-flash。

Q3: BigQuery 查詢時如何避免不小心的巨額計費？

三大安全習慣：1. 查詢前務必使用 Dry-Run 估算 bytes；2. 在 GCP BigQuery Quotas 中設定自訂的「查詢位元組配額上限」；3. 在所有日誌型與時間序列資料表上強制設定 Date-Partitioning 與 Require Partition Filter。

Q4: Antigravity 如何保證不會誤刪除生產環境的 Cloud 資源？

所有具破壞性的指令（例如刪除資料庫、刪除 Cloud Run 服務、清空 GCS Bucket），Antigravity 皆預設採取嚴格的「審查確認提示」政策，絕不在未經使用者確認前靜默執行 --quiet 刪除指令。
