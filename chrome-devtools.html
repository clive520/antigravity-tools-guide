快速使用提示

在 Antigravity 對話框中輸入 /chrome-devtools 或相關指令即可即時觸發！

官方合作擴充套件 Version 1.10.1 Token: 789 / 20,000 (3.9%)

Chrome DevTools MCP

開發者：Chrome DevTools Team

"Reliable automation, in-depth debugging, and performance analysis in Chrome using Chrome DevTools and Puppeteer."

這是 Google Chrome 團隊官方針對 AI Agent 量身打造的 **Model Context Protocol (MCP)** 擴充套件。它讓 Antigravity 的 AI 助理能直接操控底層 Chrome 瀏覽器引擎，具備全自動化操作、即時擷取 DOM、抓取網路封包、診斷效能瓶頸（如 LCP）、檢查 Cookie 認證與分析記憶體洩漏等全方位開發除錯能力。

2. 這個功能能做什麼？（核心能力）

網頁互動與自動化操作

精準模擬真人操作：點擊按鈕、輸入文字、送出表單、下拉滾動、處理彈跳視窗（Dialog）、上傳檔案及頁面截圖（Screenshot）。

效能分析與 LCP 優化

自動執行 Lighthouse Audit 稽核，針對 Core Web Vitals 中的 Largest Contentful Paint (LCP) 進行瀑布流追蹤與阻塞資源排查。

Cookie、Session 與授權排錯

即時檢查與追蹤 Cookie、Set-Cookie 標頭、診斷 SameSite、Partitioned 跨域 Cookie 問題，以及分析 401/403 登入跳轉失敗原因。

記憶體洩漏與 Heap Snapshot

擷取堆疊快照（Heap Snapshot），精確鎖定 JavaScript/Node.js 記憶體暴增源頭，自動抓出游離 DOM 節點（Detached DOM elements）。

無障礙 (a11y) 稽核

根據 web.dev 規範檢驗 ARIA 標籤、色弱色彩對比度、焦點狀態（Focus State）、鍵盤導航順序與觸控目標尺寸。

網路請求與 Console 日誌監控

攔截並分析特定 API 封包請求、狀態碼、回應主體，並即時讀取 Console 報錯或注入動態日誌點（Logpoints）。

3. 六大專屬指令（Slash Commands）深度解析

套件內建 6 款專屬的快捷指令，在 Antigravity 對話框中輸入斜線 / 即可呼叫：

/chrome-devtools 全能網頁控制與除錯引擎
通用主力模式

全面透過 MCP 調用 Chrome 進行高效除錯、頁面導航、點擊填表自動化與網路封包檢查。

> /chrome-devtools 打開 http://localhost:3000，點擊登入按鈕並檢查是否有報錯
/debug-optimize-lcp 最大內容繪製 (LCP) 與 CWV 效能調校
效能調校必備

引導診斷並優化 Largest Contentful Paint (LCP)。分析 Hero 主圖載入速度、阻斷渲染的 CSS/JS、字型載入延遲並給出具體修正方案。

> /debug-optimize-lcp 幫我分析 https://example.com 為什麼首頁加載超過 2.5 秒
/cookie-debugging Cookie、Session 與身分驗證排查
認證除錯神器

檢查與診斷 Cookie 遺失、Set-Cookie 標頭格式、SameSite 跨站限制、Partitioned Cookies（CHIPS）相容性及 Cookie 同意橫幅合規性。

> /cookie-debugging 檢查跨域呼叫 API 時 Auth Token Cookie 為什麼沒有附帶發送
/memory-leak-debugging JavaScript / Node.js 記憶體洩漏診斷
高階架構優化

當前端頁面長時間執行變慢或 Node.js 發生 OOM (Out Of Memory) 時，透過 Heap Snapshot 比較物件分佈，找出未釋放的監聽器與游離 DOM。

> /memory-leak-debugging 連續切換 5 次頁面，分析 SPA 應用的記憶體快照
/a11y-debugging 無障礙體驗與 ARIA 標籤稽核
國際通用規範

根據 Google web.dev 指南進行 a11y 審查。自動檢查缺失的 `aria-label`、對比度不足的文字、無效的鍵盤 Tab 焦點與過小的手機點擊熱區。

> /a11y-debugging 檢查首頁的按鈕與導航欄是否符合 WCAG AA 無障礙標準
/troubleshooting MCP 連線與目標埠排錯
故障排除

當 `list_pages` 或啟動 Chrome 實例失敗、CDP 埠衝突或瀏覽器權限受阻時，自動診斷環境配置並引導排除。

> /troubleshooting 無法連線至本機除錯通訊埠，請檢查 Chrome 啟動參數

4. 我該如何使用？（實戰流程與 10 大角色應用範例）

10 大專業場景全面覆蓋

不僅是單純打指令，不同專業角色（開發、測試、架構、SEO、資安）都能藉由 Chrome DevTools MCP 大幅倍增生產力：

1

Navigate / New

呼叫 `new_page` 啟動或導航至目標 URL

2

Snapshot / Wait

擷取文字結構快照，獲取元素唯一 uid

3

Action / Fill

依據 uid 執行精確點擊、填寫或截圖

4

Audit / Report

產出 Lighthouse 報表或診斷錯誤

10 大專業實戰對話提示詞 (Prompt Playbook)：

可直接複製提示詞至對話框使用
範例 01 · 前端工程師

跨裝置 RWD 斷點與移動端選單視覺抓漏

使用工具: emulate, take_screenshot, get_css_styles

痛點情境：在桌機版開發正常，但特定手機解析度下抽屜式選單（Drawer）無法彈出，或被背景遮罩擋住點擊。

> 「請幫我模擬 iPhone 14 Pro 視窗尺寸（393x852，DPR 3），打開 http://localhost:5173，點擊右上角漢堡選單按鈕，截圖檢查側邊抽屜導航是否完整展開，並用 get_css_styles 檢查導航欄的 z-index 與 CSS 變數是否被遮擋。」
預期成果：AI 自動調整 viewport、模擬點擊展開、輸出渲染截圖並列出樣式層級衝突原因。
範例 02 · 效能工程師 / SRE

電商大促促銷活動頁 LCP 與阻塞資源優化

使用指令: /debug-optimize-lcp, lighthouse_audit

痛點情境：重大行銷活動上線前夕，首頁最大內容繪製（LCP）高達 3.8 秒，影響 SEO 排名且大幅增加跳出率。

> /debug-optimize-lcp 針對我們的雙 11 促銷頁 https://shop.example.com 進行 Core Web Vitals 診斷，找出是哪張 Hero 大圖或外部 JS 阻塞了渲染，並給出使用 fetchpriority="high" 預先載入或轉換 WebP 格式的具體修正代碼。
預期成果：AI 生成完整的瀑布流資源圖、指出 LCP 元素位置，並直接給出 HTML/CSS 最佳化改寫建議。
範例 03 · QA / 測試工程師

電商端到端 (E2E) 購物車結帳與折價券自動化驗證

使用工具: fill_form, click, wait_for, take_screenshot

痛點情境：每次版本更新都要手動測試 20 分鐘重複的加購物車、填地址、套折扣碼與確認訂單流程。

> 「打開測試環境商城 http://localhost:8080/products，搜尋商品『無線降噪耳機』，將第一筆搜尋結果加入購物車，前往結帳頁面在折扣碼欄位填入『OFF2026』並送出，驗證總金額是否扣減 20%，最後將訂單確認畫面截圖回傳。」
預期成果：全程無需人手干預，AI 自動化走完整個結帳流程，並驗證金額文字與保存確認截圖。
範例 04 · 全端 / 後端工程師

跨域認證 Cookie 遺失與 CORS 403 授權排錯

使用指令: /cookie-debugging, list_network_requests

痛點情境：前端從 app.domain.com 呼叫 api.domain.com 時，授權 Cookie 莫名沒有附帶，導致 API 一律回傳 401/403。

> /cookie-debugging 前端在呼叫 https://api.example.com/v1/auth/session 時回傳 403，請幫我監聽該請求，檢查 Request Headers 中的 Cookie 是否被 SameSite 限制或缺少 Partitioned 屬性所攔截，並檢查 Response 的 Access-Control-Allow-Credentials 設定。
預期成果：精準指出 Cookie 缺少 `SameSite=None; Secure` 或 CORS 未允許 Credentials，並提供修正標頭。
範例 05 · 資安工程師 / DevSecOps

第三方腳本監控、CSP 違規與敏感 Cookie 安全標誌稽核

使用工具: list_network_requests, evaluate_script

痛點情境：需要定期確認網站沒有載入未經審核的惡意第三方 CDN 腳本，且敏感 Cookie 必須包含 HttpOnly 與 Secure。

> 「稽核登入頁面 https://admin.example.com 的網路安全性：列出頁面載入的所有外部 JavaScript 網域名稱，檢查是否有違反 Content-Security-Policy (CSP) 的行為，並確認儲存 Token 的 Cookie 是否皆有設上 HttpOnly、Secure 與 SameSite=Strict 標誌。」
預期成果：整理所有外部腳本依賴來源清單、回報缺失的安全標誌，防範 XSS 與 Session 劫持漏洞。
範例 06 · 前端架構師

SPA 單頁應用長期運行記憶體洩漏與游離 DOM 排查

使用指令: /memory-leak-debugging, take_heapsnapshot

痛點情境：監控儀表板應用在連續運作數小時後瀏覽器頁面 RAM 暴增超過 1.5GB，最後出現 Aw, Snap! 當機。

> /memory-leak-debugging 打開 http://localhost:3000/analytics，模擬點擊在『總覽儀表板』與『即時圖表』之間切換 8 次。在切換前後各擷取一份 Heap Snapshot 快照進行比對，抓出未被 GC 回收的 Chart.js 實例與游離的 Detached DOM 元素。
預期成果：分析 Retainer 樹、找出忘記呼叫 `chart.destroy()` 或未解綁的 `resize` 事件監聽器位置。
範例 07 · 無障礙專員 / 公共網站維護者

政府機關網站 WCAG 2.1 AA 無障礙標章法規稽核

使用指令: /a11y-debugging, take_snapshot

痛點情境：教育或政府機關網站必須通過無障礙 AA 標章認證，人工逐頁點擊檢查色彩對比度與報讀器標籤費時費力。

> /a11y-debugging 稽核市立圖書館預約圖書流程頁面：檢查送出按鈕與輸入框是否有正確的 aria-label 與 aria-describedby，文字色彩對比度是否達到 4.5:1，並全程使用鍵盤 Tab 鍵導航確認焦點可視指示器（Focus Outline）是否正常顯示。
預期成果：產出無障礙缺失清單，標示不符合標準的 DOM 選擇器與色彩十六進位值，並提供符合 WCAG 規範的修復代碼。
範例 08 · SEO 顧問 / 成長行銷人員

客戶端渲染 (CSR) 爬蟲收錄與 JSON-LD 結構化資料驗證

使用工具: evaluate_script, take_snapshot

痛點情境：React/Vue 單頁應用動態渲染容易讓搜尋引擎抓不到完整的 Meta Description，或 Schema.org 欄位有語法錯誤。

> 「打開最新發布的部落格文章頁面 http://localhost:3000/blog/post-101，從最終渲染完成的 DOM 中擷取 title、meta description、canonical 網址，並檢驗 script[type='application/ld+json'] 中的 Article 結構化資料欄位是否包含完整的 headline, image, author 與 datePublished。」
預期成果：驗證動態注入的 SEO 標籤是否已在客戶端正確就緒，避免搜尋引擎抓取到空白範本。
範例 09 · Chrome Extension 開發者

Manifest V3 Service Worker 背景通訊與 Popup 行為除錯

使用參數: --categoryExtensions, evaluate_script

痛點情境：Manifest V3 的背景腳本改為 Service Worker，經常因為背景休眠導致 Content Script 訊息傳遞逾時失敗。

> 「請載入我本地編譯完成的 Chrome 擴充套件目錄 ./extension-dist，觸發擴充功能的 Popup 彈出面板，點擊『開始擷取』按鈕，並進入 Background Service Worker 監聽 chrome.runtime.onMessage 事件，確認 Content Script 是否成功回傳選取的網頁文字。」
預期成果：自動載入未封裝套件（Unpacked）、觸發 UI 行為並直接檢查 Service Worker 內部狀態。
範例 10 · 技術客服與維運工程師

100% 精準重現特定機型與螢幕解析度下的偶發性 Bug

使用工具: emulate, get_console_message, list_network_requests

痛點情境：使用者回報「使用 iPad 點擊送出按鈕毫無反應」，但工程師在自己電腦上卻完全無法重現。

> 「重現客戶回報工單 #5082：客戶使用 iPad 10.2 吋橫向視窗（解析度 1080x810），在結帳步驟點擊『確認付款』卡住。請模擬該螢幕尺寸與 iPad User-Agent，執行該操作並抓取當下的 Console 報錯日誌與失敗的網路請求，整理成問題重現報告。」
預期成果：精準捕捉到觸控事件（TouchEvent）未適配所造成的 JS 報錯，生成完整 Bug 重現日誌附截圖。

6. 進階設定與環境參數配置

如果你的專案需要進行**擴充套件開發 (Chrome Extension)** 或**深層記憶體除錯 (Heap Snapshots)**，可於 MCP 設定檔中追加啟動 Flag：

// mcp_config.json 設定範例
{
  "mcpServers": {
    "chrome-devtools": {
      "command": "npx",
      "args": [
        "chrome-devtools-mcp@latest",
        "--categoryExtensions",    // 開啟 Chrome 擴充套件安裝與除錯工具
        "--memoryDebugging"        // 開啟完整 Heap 快照與記憶體分析
      ]
    }
  }
}

7. 常見問題與除錯 (FAQ)

Q1：它與一般的無頭瀏覽器（如純寫 Playwright 腳本）有何不同？

一般的 Playwright 需由工程師手動撰寫腳本；而 Chrome DevTools MCP 讓 Antigravity 的 AI Agent 能以標準協議在對話中動態執行「看畫面、做決策、點擊、看結果」的閉環操作，且原生整合 Lighthouse、Heap 快照與 Performance Timeline，除錯能力遠高於單純的瀏覽器自動化。

Q2：執行時 Chrome 會跳出視窗嗎？登入狀態能記住嗎？

預設使用獨立持久化的使用者設定檔（Persistent Chrome Profile）。如果需要登入個人帳號，可在開啟的瀏覽器視窗中手動登入一次，後續會自動保留 Cookie 與 Session。

Q3：為什麼我在截圖或找元素時會提示找不到 uid？

網頁上的元素隨動態渲染可能會改變。只要指示 AI「重新拍攝一次 take_snapshot」，AI 就會取得最新的 DOM 樹與對應的 uid，即可繼續順利點擊或填表。
