Stripe 擴充功能實戰指南
SaaS 訂閱計費、Payment Links 與財務自動化

透過 Antigravity 的 Stripe 專屬生態外掛，AI Agent 具備商業金流的完整掌控力：一鍵生成商品收款連結 (Payment Links)、自動配置月繳/年繳階梯計費、調閱交易流水對帳、管理客戶信用卡續訂狀態，並能自動防範詐欺爭議款。

1. 功能概述與生態定位

Stripe 是全球領先的金融基礎設施平台，支撐著從微型獨立開發者 (Indie Hackers) 到 OpenAI、Amazon、Shopify 等跨國巨頭的金流運作。在 Antigravity 中導入 Stripe 官方 MCP 伺服器，讓 AI 跨越了「寫代碼」的邊界，正式獲得了「直接經營商業模式」的能力。

零代碼極速收款 (Payment Links)
無需撰寫前端結帳頁，AI 一句話即可產出支援 Apple Pay / Google Pay 的全球支付網址。
現代 SaaS 週期訂閱 (Billing)
支援按用量計費 (Metered)、階梯式定價 (Tiered)、試用期 (Free Trial) 與平滑升降級 (Proration)。
AI 財務審計與防偽 (Radar)
機器學習即時評估交易風險分數，自動攔截盜刷，並智慧安排扣款失敗後的最佳重試時機。

2. 這個功能能做什麼？

Stripe 整合套件賦予 Antigravity 4 大商業變現與財務自動化維度：

SaaS 訂閱計費與客戶生命週期

自動化註冊客戶帳戶、建立月費/年費訂閱合約、設定扣款寬限期，以及處理訂閱更換時的差額比例計算。

Payment Links 與促銷折扣碼

隨時按需求生成客製化付款連結，可預先帶入促銷 Coupon 折扣碼、收集顧客收件地址，或限制購買數量。

B2B 電子商業發票與對帳

針對大額客戶開立 Net 30/60 天期國際商業發票 (Invoice)，自動寄送 PDF 與線上信用卡/ACH 轉帳付款入口。

Radar 風險控管與爭議款反擊

即時掌握盜刷風險分數，當遭遇爭議款 (Dispute / Chargeback) 時，AI 能快速整理訂單履約證明自動提交申訴。

角色 01 SaaS 創辦人 · 3 階訂閱產品與 Payment Links
stripe_payment_links

請使用 stripe 工具為我的 SaaS 服務建立三階訂閱計費體系：
1. 產品名稱：「Antigravity Assistant」
   - Starter Plan：每月 $19 USD，代碼 price_starter_monthly。
   - Pro Plan：每月 $49 USD，代碼 price_pro_monthly，提供 14 天免費試用期。
   - Team Plan：每月 $199 USD，代碼 price_team_monthly。
2. 為這三個價格方案分別產出 Stripe Payment Links。
3. 每個連結需開啟「允許使用促銷代碼 (allow_promotion_codes: true)」並設定成功結帳後跳轉至 https://app.myai.com/welcome。
4. 輸出三個連結與前端嵌入之 Pricing Table HTML/Tailwind 範例。
預期成果：AI 調用 Stripe API 建立 Product 與 Price，產出 3 組 Payment Link 網址，並附帶具現代感的三欄收費表前端代碼。
角色 02 電商財務會計 · 上月營收流水對帳與手續費拆解
stripe_balance_transactions

場景情境：月底結算，需要調閱上月所有交易紀錄，拆分銷售毛額、Stripe 處理手續費與淨提現金額，產出會計核銷報表。 

請使用 stripe_balance_transactions 調閱上個日曆月份的所有資金交易流水：
1. 篩選條件：created 在上月 1 號 00:00:00 至上月最後一天 23:59:59。
2. 匯總統計：
   - 總交易筆數 (Transactions Count)
   - 銷售總金額 (Gross Volume in USD)
   - Stripe 扣除手續費總額 (Total Processing Fees)
   - 退款總額 (Total Refunded)
   - 實際入帳淨額 (Net Payout Amount)
3. 標出其中手續費比例異常高於 3.5% 的跨國交易，並輸出成清晰的 Markdown 財務月報對帳表。
預期成果：AI 分頁拉取流水紀錄，精確計算毛額、淨額與手續費總額，並條列異常高費率訂單供財務部門核對。
角色 03 全端結帳工程師 · Webhook 簽名驗證與防掉單
stripe_webhooks

場景情境：在 Node.js / Express 或 Next.js API 實作 Stripe Webhook 接收器，必須使用 `stripe.webhooks.constructEvent` 嚴格防禦重放攻擊與偽造支付事件。 

請使用 stripe 工具為我的後端撰寫健壯的 Webhook 處理器（TypeScript）：
1. 監聽端點：/api/stripe/webhook，正確讀取原始二進位 body (raw-body)。
2. 使用 STRIPE_WEBHOOK_SECRET 驗證「stripe-signature」標頭，防範中間人偽造請求。
3. 嚴謹處理以下關鍵事件：
   - checkout.session.completed：將訂單標記為已付款，發放用戶 SaaS 權限。
   - invoice.payment_failed：記錄扣款失敗，發送郵件通知客戶更新信用卡。
   - customer.subscription.deleted：降級用戶權限至免費版。
4. 加入防重複消費機制（Idempotency），確保同一個 event_id 不會重複發放點數。
預期成果：AI 提供兼顧資安防禦與冪等性 (Idempotency) 的後端程式碼，附帶 Stripe CLI 本機觸發測試事件指令。

角色 05 客服爭議處理員 · 爭議款 (Dispute) 舉證反擊
stripe_disputes

場景情境：收到來自發卡銀行的「未授權交易」爭議款 (Chargeback)，必須在 7 天舉證期內整理客戶登入 IP、數位商品下載紀錄與對話紀錄提出反駁。 

請使用 stripe 工具查詢爭議編號為「dp_1Pxxxxxx」的案件詳情：
1. 檢視爭議原因（Reason）、被扣押金額與發卡機構要求的反駁截止日期。
2. 協助組織有效抗辯證據（Evidence Submission）：
   - 客戶電子信箱與購買時填寫姓名。
   - 伺服器存取日誌：顯示該客戶在購買後 5 分鐘內使用相同 IP (118.163.xx.xx) 登入並下載數位授權碼。
   - 服務條款條文連結：明確載明數位商品開通後不予退貨之約定。
3. 撰寫一份專業嚴謹的英文反駁陳述信 (Evidence Text)，準備提交給銀行審查。
預期成果：AI 解析爭議款狀態，按照 Visa/Mastercard 規範整理關鍵證據格式，並草擬高勝訴率的英文申訴說明。

請使用 stripe_subscriptions 為客戶「cus_Nxxxxxx」執行訂閱方案即時升級：
1. 查詢其現有作用中訂閱項目（sub_xxxx）。

角色 08 財務長 (CFO) · SaaS 核心營運指標 (MRR / Churn) 計算
stripe_analytics

場景情境：在召開董事會前夕，需要統計近一季的 MRR (月經常性營收)、ARR、客戶流失率 (Churn Rate) 與平均顧客價值 (LTV)。 

請使用 stripe 工具分析我所有 active 狀態的訂閱合約：
1. 統計當前總作用中訂閱數 (Active Subscriptions)。
2. 計算目前實時月經常性營收 (Current MRR = 月繳合約金額總和 + 年繳合約總和/12)。
3. 統計過去 30 天內主動取消 (canceled) 或扣款失敗被終止的訂閱數量，計算月客戶流失率 (Logo Churn Rate)。
4. 預估當前用戶之 ARPU (每用戶平均收入) 與預估 LTV (顧客終生價值)。
5. 產出一份供投資人閱覽的簡潔財務儀表板摘要。
預期成果：AI 精確聚合 Subscription 數據，計算出關鍵 SaaS 指標並結構化排版為管理階層決策報表。
角色 09 資安風控官 · Stripe Radar 詐欺防禦規則設定
stripe_radar

場景情境：防範來自匿名 VPN 節點與無 3D Secure 驗證的高風險盜刷卡片，設定自定義 Radar 阻斷規則。 

請使用 stripe 工具為我的支付網關規劃 Radar 詐欺防範策略：
1. 阻斷規則 (Block Rule)：
   - 當 :risk_score: > 75（極高風險交易）時，直接拒絕付款。
   - 當發卡國與客戶連線 IP 所在國不一致，且金額大於 $500 USD 時，強制阻斷。
2. 審查規則 (Review Rule)：
   - 當 :risk_score: 介於 60 至 75 之間時，標記為 Manual Review 人工審查。
3. 3D Secure 驗證規則：
   - 針對所有非 3DS 驗證通過且金額大於 $100 USD 的跨國交易，要求觸發 3DS 簡訊/APP 認證。
4. 提供規則設定語法與誤殺率降低指引。
預期成果：AI 提供符合 Stripe Radar 語法規則的防護表達式，有效降低盜刷拒付率至 0.1% 以下。

場景情境：每月因信用卡過期或額度不足導致被動流失 (Involuntary Churn)，配置 Smart Retries 與自動化卡片即將過期通知。 

請使用 stripe 工具為我的 SaaS 訂閱配置防流失 (Dunning Management) 機制：
1. 開啟 Stripe 機器學習 Smart Retries：在 3 週內於最佳時間點智慧重試扣款最多 4 次。
2. 配置客戶提醒信：
   - 信用卡將在 30 天內過期時，自動發送信件提醒更新。
   - 第一次扣款失敗時，自動寄送包含專屬安全更新連結 (Customer Portal) 的通知信。
3. 扣款重試全數失敗後之處置：不要立即刪除訂閱，將合約標記為「unpaid」，保留 7 天寬限期。
4. 輸出完整的 Dunning 策略流程圖與客戶通知信繁體中文範本。
預期成果：AI 提供完整的自動扣款失敗補償排程設定，以及語調客氣專業的客戶卡片更新提醒信件範本。

5. 安裝外掛與設定教學

步驟一：於 Antigravity 外掛市場安裝

在 Antigravity 外掛管理員中搜尋並安裝 Stripe 官方生態外掛：

antigravity-plugins-partners/plugin/stripe

步驟二：設定 Stripe 密鑰與 Webhook 密鑰

在 Stripe Developers 後台取得 sk_test_... 或正式 sk_live_... 密鑰，並配置於環境變數：

# Stripe API 密鑰配置
STRIPE_SECRET_KEY="sk_test_51Px..."
STRIPE_WEBHOOK_SECRET="whsec_..."

步驟三：搭配 Stripe CLI 進行本地測試

推薦在終端機安裝 Stripe CLI，方便在本地即時轉發 Webhook 事件至本機開發埠：

stripe login && stripe listen --forward-to localhost:3000/api/stripe/webhook

6. 常見問題 (FAQ)

Payment Links 與 Stripe Checkout 有何不同？

Payment Links 是零代碼產生的固定靜態收款網址，適合貼在社群或 Email；Checkout Session 則是動態透過後端 API 生成，支援高度客製化購物車與回呼。

測試環境 (Test Mode) 與正式環境如何切換？

只需切換 API Key 前綴即可：以 sk_test_ 開頭為沙盒測試模式，以 sk_live_ 開頭則為正式營業扣款模式。

什麼是 Customer Portal (客戶自助後台)？

Stripe 內建的安全託管頁面，客戶可自行在此查看歷史發票、更換綁定信用卡或升降級/取消訂閱，無需工程師從頭撰寫會員中心。

如何防止 Webhook 重複處理 (Idempotency)？

每個 Stripe 事件均包含唯一的 event.id。在後端資料庫記錄已處理的 Event ID，處理前先查詢是否存在即可百分之百避免重複發放商品或扣款。
