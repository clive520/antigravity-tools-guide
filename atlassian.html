Atlassian TWG CLI 實戰指南
Jira 敏捷需求、Confluence 知識庫與 Bitbucket PR 企業脈絡圖譜

透過 Antigravity 的 Atlassian Teamwork Graph CLI (TWG) 專屬外掛，AI Agent 具備了深度理解巨型企業工作脈絡的超能力：一鍵以 JQL 語義檢索 Jira 待辦項目、查閱與更新 Confluence 架構文檔、追蹤 Bitbucket PR 審查狀態，並在跨部門專案間建立全景脈絡圖譜。

1. 功能概述與生態定位

在大型企業與跨國科技巨頭中，團隊協作常分散於三大系統：Jira（追蹤任務進度）、Confluence（沉澱架構設計與政策）、Bitbucket（版本控制與審查）。過去 AI 只能孤立操作單一工具，常出現「看得到 PR 卻找不到原始需求」、「看得到 Jira 票卻漏掉 Confluence 決策依據」的資訊斷層。

Atlassian Teamwork Graph CLI (TWG) 是 Atlassian 官方專為 Coding Agents 設計的統一中樞，透過 Graph 實體關聯模型，將人（People）、需求（Issues）、文件（Pages）與代碼（Pull Requests）無縫黏合為立體脈絡。

Jira JQL 精準下鑽
支援全功能 Jira Query Language，精確篩選跨季度、跨專案、跨 SLA 逾期之高風險工單。
Confluence 活態知識庫
AI 可直接搜尋企業 Wiki，自動產生架構決策紀錄 (ADR) 與 PRD 規格書，並排版上線。
Bitbucket 企業審查閉環
將代碼審閱意見直接關聯回對應 Jira 驗收準則，確保每一次 Merge 皆具備合規可追溯性。

2. 這個功能能做什麼？

Atlassian TWG CLI 整合套件賦予 Antigravity 4 大企業級協作護城河：

Jira 敏捷需求管理與工作流自動化

撰寫 JQL 查詢、批次更新工單狀態（Open -> In Progress -> Closed）、指派處理人員、維護 Story Points 與 Sprint 週期。

Confluence 企業百科檢索與架構文件撰寫

檢索歷年技術架構規格、撰寫軟體架構決策 (ADR)、建立產品規格 (PRD) 與重大故障復盤紀錄 (Post-Mortem)。

Bitbucket PR 程式審查與審計追溯

自動稽核所有 Pull Request 是否符合合規標準、檢查是否綁定 Jira 票號、統整 Reviewer 留言與代碼變更 Diff。

Teamwork Graph 跨組織知識大腦

以圖譜形式查詢「誰負責什麼」、「這份文件跟哪些 PR 與工單相依」，在大型複雜系統中精確定位利害關係人。

4. 10 大跨角色實戰 Prompt

覆蓋企業架構師、Jira 管理員、DevOps、資安長與敏捷教練等全維度實戰

10 個高階範例
角色 01 企業架構師 · 舊架構檢索與新微服務拆分 ADR
atlassian_confluence_create

場景情境：在 Confluence 搜尋團隊過去關於會員系統的技術文件，並為即將進行的微服務拆分撰寫一份標準架構決策紀錄 (ADR)。 

請使用 atlassian_confluence 工具協助完成架構重構規劃：
1. 先在空間「ARCH」檢索標題含「User Service Architecture」或「Monolith Auth」的既有頁面，摘要其核心資料庫依賴。
2. 在空間「ARCH」建立全新頁面「ADR-089: 拆分會員鑑權微服務與事件驅動架構」：
   - Context (背景)：單體架構中 Auth 模組在促銷期間造成 DB 連線數耗盡。
   - Decision (決策)：採用 Go 語言重寫 Auth 服務，引入 Redis 快取 Session，並透過 Kafka 發布用戶註冊事件。
   - Consequences (影響與代價)：需維護跨服務分散式事務與資料一致性補償。
3. 自動將此 ADR 關聯至 Jira Epic「ARCH-2026-MIGRATION」。
預期成果：AI 快速提取舊文檔痛點，撰寫出符合標準 Michael Nygard 規範的專業 ADR 並排版發布至 Confluence。
角色 02 Jira 專案管理員 · 複雜 JQL 抓出延宕工單與 SLA 稽核
atlassian_jira_query

場景情境：為跨部門專案進行健康度體檢，找出逾期未交付且 SLA 已違規的所有 High/Blocker 工單。 

請使用 atlassian_jira_query 執行精密 JQL 查詢並產出風險預警報告：
1. 查詢語法 JQL：
   project in ("CORE", "FIN", "APP") AND priority in ("Blocker", "High") AND status not in ("Done", "Closed", "Resolved") AND duedate < now() ORDER BY duedate ASC
2. 分析查詢結果：
   - 逾期天數大於 14 天的嚴重滯留工單。
   - 負責人統計：哪些工程師身上積壓了超過 3 張以上的逾期高風險工單。
3. 輸出 Markdown 格式的「SLA 逾期風險清單」，包含 Jira ID、摘要、負責人與建議介入方案。
預期成果：AI 解析 JQL 檢索結果，精確抓出專案管理盲點與人力瓶頸，協助團隊即時調整研發資源。
角色 03 跨團隊專案經理 · Teamwork Graph 聚合專案全景
atlassian_graph_context

場景情境：新任專案經理接手代號為「Project Titan」的跨部門大案，需一鍵聚合所有相關 Jira 需求、Confluence 規格與 Bitbucket PR。 

請使用 atlassian_graph_context 查詢專案「PROJ-TITAN」的完整關聯脈絡圖譜：

2. 找出所有引用或被該 Epic 鏈結的 Confluence 規格頁面（PRD、UI/UX 設計規範）。
3. 統計已開啟與已合併的 Bitbucket Pull Requests 總數與代碼審閱涵蓋率。
4. 繪製一份以 Mermaid 圖表表示的「全系統實體相依關係圖」，包含核心利害關係人名單。
預期成果：AI 調用 Teamwork Graph API 串聯跨系統節點，產出結構清晰的 Mermaid 關聯圖與全域綜覽報告。
角色 04 DevOps 導入專家 · Bitbucket PR 與 Jira 合規稽核
atlassian_bitbucket_link

場景情境：為滿足 SOC2 / ISO27001 合規審查，稽核本月 Bitbucket 儲存庫中所有 Merge 至 main 分支的 PR 是否皆嚴格關聯審批通過的 Jira 票號。 

請使用 atlassian_bitbucket_link 稽核「payment-service」倉庫過去 30 天的合併記錄：
1. 遍歷所有已合併 (Merged) 的 Pull Requests。
2. 檢查條件：
   - PR 標題或分支名稱是否包含合法 Jira Issue Key（如 PROD-XXXX）。
   - 該對應 Jira 工單狀態是否已抵達「Approved」或「Verified」。
   - 是否包含至少 2 位資深 Reviewer 的 Approve 簽核。
3. 標記出任何「孤兒 PR（無對應 Jira）」或「未經 2 人審批強制合併」的違規項目，產出合規稽核清冊。
預期成果：AI 比對代碼庫歷史與工單審批紀錄，提供合規性百分比指標與異常清單，滿足高規格稽核需求。
角色 05 企業資安稽核員 · Confluence 敏感權限空間掃描
atlassian_confluence_read

場景情境：清查 Confluence 內部 Wiki 中是否存在被誤設為「全公司公開 (Anonymous/All Users)」的敏感空間（如薪酬、商業機密與金鑰備忘）。 

請使用 atlassian 工具協助執行企業知識庫安全合規掃描：
1. 檢視 Confluence 中所有 Spaces 的權限矩陣。
2. 找出關鍵字涉及「Salary」、「Credential」、「Secret」、「API Key」、「Investor Terms」的頁面。
3. 檢查這些頁面的權限限制（Restrictions），確認是否開放給「All Employees」或未經受限的群組。
4. 輸出資安風險清單，建議應立即限縮為「僅限 C-Level 與 HR Admin」的頁面連結與具體修正指引。
預期成果：AI 提供具備敏感資料外洩風險的頁面清單，並產出權限收斂的最佳實踐建議。
角色 06 資深業務分析師 (BA) · 會議重點轉換為 Confluence PRD

場景情境：將與業務部門進行的 1 小時訪談文字稿，迅速轉化為符合 Atlassian 官方產品需求文件標準模板的 Confluence 頁面。

角色 07 產品維運 SRE · 重大故障復盤 (Post-Mortem) 彙整
atlassian_confluence_create

場景情境：昨日 Production 環境發生 25 分鐘的支付中斷事故 (Sev-1)，需聚合 Jira 應變工單日誌與 Slack 紀錄，產出無指責事故檢討書。 

請使用 atlassian 工具為昨日事故建立完整的 Post-Mortem 檢討文檔：
1. 查詢事故工單「INCIDENT-892」中記錄的時間戳記與處置日誌。
2. 在空間「SRE」建立「Incident Post-Mortem: 2026-11-23 Payment Gateway Timeout」：
   - 事故摘要：Sev-1 等級，影響 1,200 名用戶，中斷時長 25 分鐘。
   - 完整時間軸 (Timeline)：從 14:02 監控發報，到 14:15 隔離故障節點，至 14:27 服務完全恢復。
   - 根本原因 (Root Cause - 5 Whys 分析)：DNS 輪詢設定錯誤導致負載傾斜至單一伺服器。
   - 預防行動項 (Action Items)：自動在 Jira 建立 3 張預防性改善工單並指派給維運小組。
預期成果：AI 自動將事故歷程整合成高規格復盤報告，並自動派發 Jira 改善任務，落實可靠性工程閉環。

5. 安裝外掛與設定教學

步驟一：於 Antigravity 外掛市場安裝

在 Antigravity 外掛管理員中搜尋並安裝 Atlassian 官方合作夥伴外掛：

antigravity-plugins-partners/plugin/atlassian-twg-cli

步驟二：設定 Atlassian 網域與 API Token

前往 Atlassian Account Settings > Security > API Tokens 建立個人金鑰，並於專案環境變數配置：

# Atlassian 存取憑證
ATLASSIAN_INSTANCE_URL="https://your-company.atlassian.net"
ATLASSIAN_USER_EMAIL="engineer@company.com"
ATLASSIAN_API_TOKEN="your_api_token_here"

步驟三：驗證 Teamwork Graph CLI 連線

在終端機執行測試指令，確認是否成功連通 Jira 與 Confluence 空間：

atlassian-twg whoami && atlassian-twg jira list-projects

6. 常見問題 (FAQ)

什麼是 Teamwork Graph (TWG)？

它是 Atlassian 底層的語義脈絡圖譜，專為 AI 代理設計，能夠將人員、工單、文件、程式碼跨系統自動關聯為動態知識網絡。

JQL 查詢速度慢如何優化？

建議查詢時優先加入 project = ... 與 status category 索引條件，避免對巨型企業全部歷史工單進行全文模糊掃描。

AI 是否會覆蓋 Confluence 既有版本？

不會。Confluence 具備完整版本歷史 (Page History)，AI 每次更新皆會產生全新的修訂版本，可隨時一鍵還原至任何時間點。

支援 Jira Data Center (地端私有部署) 嗎？

該外掛主要針對 Atlassian Cloud 進行最佳化。若為地端私有 Data Center 版本，需確認 REST API v2/v3 端點具備對應存取權限。
