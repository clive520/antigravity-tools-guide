n8n 開源自動化工作流與 Agent 編排

透過自然語言指揮全球最強大的開源自動化中樞 n8n。Antigravity AI Agent 能直接為您的工作流搭建 Webhook 觸發器、組裝資料清洗節點、排錯 JavaScript 表達式，並串接 Slack、Telegram、Shopify、Stripe、PostgreSQL 等超過 400 種雲端服務，建構高自主性 Multi-Agent 系統。

1. 功能概述與生態架構

企業常面臨不同 SaaS 應用各自為政的資料孤島難題。n8n 提供了具備高度可自託管 (Self-Hosted) 的視覺化工作流引擎。Antigravity 的 n8n 擴充套件讓使用者不必在畫布上手動拉線，直接用對話即可完成整個管線的設計與監控：

節點結構自動生成

自動生成合法的 n8n 工作流 JSON 拓撲圖，包含 Webhook, Code, IF, Switch, Loop 等控制流節點。

即時測試與單步調試

直接呼叫 `n8n_execute_workflow` 傳送測試 Payload，提取各節點輸出資料，迅速修正語法錯誤。

AI Agent 原生整合

支援 n8n 進階的 AI Agent 節點、向量資料庫 (Pinecone/Qdrant) 連線與長短期記憶模組配置。

2. 這個功能能做什麼？

跨平台 Webhook 事件連動與即時告警

接收 Stripe 支付成功、GitHub CI 崩潰、Shopify 訂單建立等事件，毫秒級自動轉發通知至 Slack, Telegram, Discord 或 Teams。

排程 ETL 資料同步與雙向清洗

設定 Cron 定時排程，每天凌晨自動抓取第三方 API 資料、過濾去重、清洗日期格式，並批量寫入 PostgreSQL 或 Google Sheets。

失敗執行紀錄 (Execution Logs) 自動排錯

當工作流發生錯誤中斷時，AI 自動讀取 `n8n_get_executions` 萃取 Stacktrace 崩潰原因，指出是哪一個節點的 JSON 欄位遺失。

憑證安全隔離 (Credentials Management)

嚴格遵循資安規範，所有 API 金鑰與 OAuth 連線均儲存於 n8n 內部的安全憑證庫中，工作流代碼中絕不暴露敏感私鑰。

3. 核心工具架構與 MCP API

MCP 工具名稱 核心參數 回傳型態 功能說明與最佳實務
n8n_list_workflows active, tags, limit Workflow List 檢索 n8n 實例中的所有工作流清單及其啟用狀態
n8n_get_workflow id Workflow JSON 取得特定工作流的完整節點與連線拓撲結構，供 AI 審查與修改
n8n_create_workflow name, nodes, connections New Workflow 建立全新自動化管線，AI 會自動計算節點於視覺畫布上的合適座標
n8n_activate_workflow id, active: boolean Success Object 一鍵啟用或暫停工作流（開始接收生產環境的 Webhook 流量）
n8n_get_executions workflow_id, status: 'error' Executions Array 提取失敗執行的詳細堆疊日誌，精準定位故障節點名稱

範例 01 自動化架構師：Stripe 支付 Webhook 接收、開通會員並同步 Discord 邀請

情境描述： 用戶在官網購買 VIP 訂閱後，需在 3 秒內完成：寫入資料庫開通用戶權限、寄送 HTML 歡迎信並透過 Discord Bot 自動發送專屬私密伺服器邀請碼。 

請使用 `n8n` 擴充功能，為我搭建一條生產級支付自動化工作流：
1. 工作流名稱：「Stripe Payment to VIP Onboarding」。
2. 節點拓撲結構：
   - 節點 1：`Webhook` 觸發器（監聽 `POST /stripe-charge-success`，開啟簽名驗證）。
   - 節點 2：`IF` 節點（檢查 `event.type == 'checkout.session.completed'`）。
   - 節點 3：`Postgres` 節點（執行 SQL `UPDATE users SET tier = 'vip' WHERE email = $1`）。
   - 節點 4：`SendGrid / Gmail` 節點（發送帶有使用者名稱的品牌歡迎信）。
   - 節點 5：`Discord` 節點（呼叫 Webhook 在管理員頻道通報：「🎉 新增 VIP 用戶：{email}」）。
3. 錯誤處理：設定 `Error Trigger` 節點，若資料庫寫入失敗，發送 Slack 緊急告警。
4. 輸出建立後的工作流 JSON 並直接在我的 n8n 實例中建立該管線。
預期執行成果：

AI 自動建立具備 6 個節點的完整工作流並配置各節點間的資料映射，一鍵部署上線。

範例 02 DevOps 工程師：GitHub CI 失敗自動觸發 Telegram 告警與日誌摘要

情境描述： 當主幹 main 分支的 GitHub Actions CI 流水線崩潰時，維運團隊需在 Telegram 頻道第一時間收到通知，包含提交者名稱與失敗 Job 連結。 

請在 n8n 中建立「GitHub Actions CI Failure Alert」管線：
1. 觸發條件：`GitHub Trigger` 節點（事件：`workflow_run`，狀態：`completed`）。
2. 過濾條件：使用 `Filter` 節點判斷 `{{$json.workflow_run.conclusion}} == 'failure'`。
3. 格式化訊息：使用 `Code` 節點（JavaScript）組裝 Markdown：
   - 🚨 **CI/CD 流水線失敗！**
   - 專案倉庫：`{{$json.repository.full_name}}`
   - 觸發分支：`{{$json.workflow_run.head_branch}}`
   - 提交作者：`{{$json.workflow_run.head_commit.author.name}}`
   - 查看失敗 Log：[點擊前往 Actions 頁面]({{$json.workflow_run.html_url}})
4. 發送行動：串接 `Telegram` 節點發送至維運小組群組，開啟靜音推播以外的高優先級提示。
預期執行成果：

AI 完成 GitHub Trigger 與 Telegram Bot 串接，大幅縮短線上故障排查的反應時間。

範例 03 電商營運：Shopify 新訂單同步寫入 Google Sheets 並觸發庫存警戒

情境描述： 每當 Shopify 門市有新訂單成立，需將訂單項目展開並逐行寫入 Google Sheets 營運總表，當剩餘庫存低於 10 件時發信通知倉管。 

請在 n8n 建立「Shopify Order Ingest & Stock Alert」工作流：
1. 觸發器：`Shopify Trigger`（事件：`Order Created`）。
2. 陣列展開：使用 `Item Lists` 節點展開訂單中的多項購買商品（Line Items）。
3. 寫入試算表：呼叫 `Google Sheets` 節點，追加行至「2026 全年訂單流向」，欄位包含：訂單號、訂購人、SKU、品名、數量、單價、總額。
4. 庫存判定：串接 `Shopify` API 查詢該 SKU 剩餘庫存，若 `< 10`，自動觸發 `Gmail` 發信給 `warehouse@example.com` 提醒及時補貨。
預期執行成果：

AI 自動配置 Item Lists 展開與條件判斷，實現電商訂單自動化入帳與缺貨預警。

範例 05 資安營運：異常登入 Webhook 呼叫 VirusTotal 查詢惡意 IP

情境描述： 系統偵測到暴力破解或異常登入嘗試時，自動將來源 IP 送交威脅情資 API 查詢，若確認為惡意節點立即通知資安工程師。 

請在 n8n 中搭建「Automated Threat Intelligence Checker」：
1. 觸發器：`Webhook`（接收 Auth0 / Firebase Auth 異常登入日誌）。
2. 提取參數：`client_ip` 與 `user_agent`。

4. 門檻告警：若 `malicious_score >= 3`，自動呼叫 `Slack` 節點在 `#security-soc` 發出高嚴重度警報，包含地理位置、ISP 與封鎖建議。
預期執行成果：

AI 自動化編排安全威脅情資過濾流程，建立企業資安防禦的第一道無人防線。

範例 07 資料工程師：排程定時 (Cron) 爬取匯率 API 並批量寫入 PostgreSQL

情境描述： 跨國電商平台需每天上午 9 點自動抓取即時外匯牌價，計算基準幣值並寫入資料庫供即時結算使用。 

請在 n8n 中建立「Daily Forex Rate Ingestion Pipeline」：

預期執行成果：

定時排程穩定運行，自動容錯重試並安全寫入關聯資料庫。

5. n8n 自動化四大工程守則

守則一：必備 Error Trigger 異常補償

生產環境中的關鍵工作流（特別是金流與資料寫入），必須在設定中指定「Error Workflow」。當管線中任一節點爆發未預期異常時，自動補發告警並記錄故障數據。

守則二：Webhook 簽名強檢驗

公開暴露的 Webhook 端點切勿以純明文接收。應在進入核心業務邏輯前，比對 HMAC-SHA256 簽章（如 Stripe-Signature, GitHub-Signature），防範偽造請求。

守則三：指數退避重試 (Exponential Backoff)

呼叫外部第三方 API 的 HTTP Request 節點，應開啟「Retry On Fail」並設定合理的等待間隔，避免因短暫網路微斷造成整筆工作流中斷。

守則四：機密憑證與代碼完全解耦

嚴禁在 Code 節點或表達式中寫入硬編碼的 API Token。應一律引用 n8n Credentials 機制，確保匯出工作流 JSON 時不發生機密洩漏。

7. 常見問題與除錯指南 (FAQ)

Q1: 為什麼 Webhook 節點無法收到外部發送的請求？

有兩種常見原因：1. 工作流尚未「啟用 (Active)」，在測試時必須使用 Test URL 並手動點擊「Listen for test event」；2. 自託管 n8n 未設定 `WEBHOOK_URL` 環境變數，導致 Webhook 回傳內部 localhost IP。

Q2: 陣列資料傳遞時，為什麼後續節點只執行了第一筆？

n8n 遵循 Item-based 執行模型。如果您的資料包裝在單一物件中的陣列欄位內，必須先通過「Item Lists」節點的「Split Out Items」動作將其打散成多個獨立 items，後續節點才會自動進行迴圈遍歷執行。

Q3: 如何備份或導出由 Antigravity 建立的工作流？

隨時可對 Antigravity 說「幫我導出 Workflow ID 為 12 的完整 JSON 代碼」，AI 會調用 `n8n_get_workflow` 並將其格式化儲存為本地 `.json` 檔案，方便納入 Git 版本控制。
