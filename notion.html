Notion Official Partner Database & Block 自動化 Second Brain 數位知識庫

Notion 企業知識庫與資料庫中樞

透過自然語言操控全球最普及的筆記與協作平台 Notion。Antigravity AI Agent 能直接檢索全工作區文檔、在多維資料庫 (Database) 中依據特定狀態過濾新增資料列、自動生成格式完美的 Callout 與折疊清單，打造無縫連結的個人數位大腦與企業 SOP 知識庫。

1. 功能概述與生態架構

Notion 以其獨特的「頁面即資料庫、區塊即樂高 (Block-based)」架構聞名。Antigravity 透過官方 Notion MCP 伺服器，將使用者的語義意圖無損對齊至 Notion 的物件模型：

多維資料庫結構化操作

支援多條件 Filter 與 Sort 查詢，精確更新 Status、Tags、Select、Date 與 Relation 關聯欄位。

豐富區塊排版 (Rich Blocks)

自動產生醒目的 Callout 提示框、折疊選單 (Toggle)、代碼塊 (Code Block) 與任務勾選清單 (To-do List)。

全工作區即時語義檢索

透過關鍵字快速穿透數百個頁面與資料庫，快速擷取歷史會議紀錄、專案規格或技術文件做為上下文。

2. 這個功能能做什麼？

專案 Sprint 看板自動推進與燃盡更新

在晨會或驗收後，直接指示 AI 查詢所有「In Progress」的任務卡片，根據 PR 合併狀態批次更新為「Done」，並自動計算本週任務完成度。

會議錄音逐字稿秒轉結構化 Action Items

輸入雜亂的會議逐字稿，AI 自動梳理核心決策、待辦事項 (Checklist) 與負責人，直接附加建立至「Team Meetings」專屬頁面中。

企業 Wiki 與客服 SOP 知識庫智慧維護

每當產品發布新功能或政策變更，AI 自動檢索相關 SOP 頁面並進行增補修改，確保客服與業務人員查閱的資訊始終是最新的版本。

Second Brain (PARA 框架) 靈感自動歸類

隨手丟入零碎的網路好文連結或靈感筆記，AI 遵循 PARA（Projects, Areas, Resources, Archives）框架自動判斷所屬分類並寫入對應資料庫。

3. 核心工具架構與 MCP API

MCP 工具名稱 核心參數 回傳型態 功能說明與最佳實務
notion_search query, filter, page_size Search Results 全域檢索頁面與資料庫標題，快速取得 page_id 或 database_id
notion_query_database database_id, filter, sorts Page Rows Array 多維資料庫查詢，支援複雜巢狀 AND/OR 條件與多欄位排序
notion_create_page parent, properties, children New Page Object 在指定父頁面建立新筆記，或在指定資料庫中新增一筆結構化列紀錄
notion_append_block_children block_id, children Blocks Array 在頁面末尾追加排版區塊（標題、內文、Callout、代碼塊、清單等）
notion_update_page_properties page_id, properties Updated Page 精準修改資料庫卡片的特定屬性（如將 Status 改為 Done、更換負責人）

範例 01 專案經理：自動彙整跨專案進度，更新 Sprint Roadmap 資料庫狀態

情境描述： 週五下班前需盤點目前正在進行的「Q2 Sprint 4」所有任務卡片，將已在 GitHub 合併的項目推進為「Done」，並統計待完成數。 

請使用 `notion` 外掛協助我整理專案看板：
1. 查詢資料庫「Engineering Sprint Tracker」：
   - 篩選條件：`Sprint == '2026-Q2-S4'` 且 `Status != 'Done'`。
2. 檢查各任務對應的 GitHub PR 狀態（比對 PR 連結屬性）。
3. 針對 PR 已合併 (Merged) 的任務卡片：
   - 調用 `notion_update_page_properties` 將 `Status` 改為 `Done`。
   - 將 `Completion_Date` 填入今日日期。
4. 在「Sprint Summary 2026-Q2-S4」頁面底部追加一段 Callout 區塊，標明總任務數、已完成數與當前進度百分比（如：85% 完成）。
預期執行成果：

AI 自動遍歷資料庫過濾卡片，批次更新已完成項目並在總結頁面寫入包含視覺進度條的排版區塊。

5. Notion 自動化四大架構守則

守則一：Database ID 精準鎖定

Notion 的 Database ID 通常是一串 32 位的英數字（可在資料庫右上角「Copy link」中獲得）。操作前務必確認該資料庫已被分享 (Share) 給您的 Integration 機器人。

守則二：屬性型別嚴格校驗

更新資料庫屬性時，型別必須 100% 吻合（例如 Multi-select 需傳入陣列、Date 需傳入 ISO 8601 格式 `YYYY-MM-DD`、Title 必須為 RichText 陣列），避免 API 拋出 400 Bad Request。

守則三：Block 階層深度限制

Notion API 對於一次性寫入的 Block 數量（建議單次不超過 100 個 blocks）與巢狀深度有嚴格限制。大型文章應採用批次追加分段寫入。

守則四：以封存 (Archive) 代替硬刪除

在自動化清理過期卡片時，強烈建議將頁面屬性設為 `archived: true` 移入垃圾桶，而非直接物理抹除，保障團隊歷史資料隨時可救援回滾。

6. 安裝與 Notion API 授權設定

透過 Notion 官方 Internal Integration 取得安全憑證並綁定頁面存取權限。

1 安裝 Notion Marketplace 外掛套件

在 Antigravity 對話框中輸入安裝指令：

/plugin install antigravity-plugins-partners/plugin/notion
2 建立 Notion Internal Integration 與取得 Token

前往 notion.so/my-integrations 點選「New integration」，命名後取得「Internal Integration Secret」（格式如 `secret_...`），並設定環境變數：

export NOTION_API_KEY="secret_..."
3 重要：將目標頁面/資料庫連線分享 (Connect) 給整合機器人

在 Notion 中開啟您欲讓 AI 存取的目標頁面，點擊右上角「...」➜ 選擇「Connect to」➜ 點選您剛才建立的 Integration 名稱，授權讀寫權限。

7. 常見問題與除錯指南 (FAQ)

Q1: 執行時報錯「Could not find database with ID: ...」？

這是最常見的權限問題！Notion 的安全性設計要求「每個頁面或資料庫必須顯式被分享給該 Integration」。請至該資料庫右上角「...」選單，在「Connect to」中確認已經連結您的機器人。

Q2: 如何從 Notion 網址取得真正的 Database ID？

複製資料庫連結時，網址格式通常為 `notion.so/workspace/1234567890abcdef1234567890abcdef?v=...`。在問號 `?` 之前的 32 個英數字串就是真正的 Database ID。直接把完整網址貼給 Antigravity，AI 也會自動提取。

Q3: 新增 Multi-select 標籤時出現錯誤？

Notion 支援在寫入時自動建立未曾出現的新標籤，但 Integration 必須擁有寫入該資料庫 Schema 的權限。若資料庫被設為「Locked (鎖定)」，則無法新增未預先定義的新標籤。
